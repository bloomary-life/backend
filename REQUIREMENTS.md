# Requirements — Bloomary backend

Format and evidence rules: [CONTRIBUTING.md](CONTRIBUTING.md). Check: `scripts/trace-check.sh REQUIREMENTS.md .`.

| ID | Requirement (When X, Y.) | Source | Status |
|---|---|---|---|
| BE-001 | When a member publishes a draft manually with its `draftId`, that draft's pending, retry or needs-review schedule is cancelled, so the worker never posts it twice. | Kat, 2026-10-22 | active |
| BE-002 | When a member sends `DELETE /api/linkedin/schedule?draftId=…`, that draft's pending, retry or needs-review schedule is cancelled and leaves the active schedule list. | Kat, 2026-10-22 | active |
| BE-003 | When no custom root pool is configured, StoreKit JWS chains are trusted only if they end at Apple Root CA - G3, so a leaf from any other public CA is rejected. | Nightly review 2026-10-24 | active |
| BE-004 | When a scheduled post hits the LinkedIn daily limit, the job is marked failed at once instead of being retried. | Nightly review 2026-10-24 | active |
| BE-005 | When a post is published or feedback is sent, `posts_publish_total` and `feedback_total` grow by one (recorded by the gate only, not again by the story). | Nightly review 2026-10-24 | active |
| BE-006 | When a draft sync request has an invalid upsert (missing id, body too long), it is rejected before any stored draft image is deleted. | Nightly review 2026-10-24 | active |
| BE-007 | When a response body is logged, draft text, profile names and pictures, MCP content, URL signatures and any non-JSON body are redacted. | Nightly review 2026-10-24 (GDPR) | active |
| BE-008 | When an MCP client with `insights:read` calls `list_insights`, it gets only the signed-in member's insights (filtered by `since` and `unused_only`); `mark_insight_used` with `insights:write` links an insight to that member's own draft. | Content engine plan, Kat 2026-10-30 | active |
| BE-009 | When a signed-in member starts a Telegram link in Bloomary, the bot links that Telegram only after the member taps the number Bloomary showed; webhook calls without the `X-Telegram-Bot-Api-Secret-Token` secret are rejected. | Content engine plan, Kat 2026-10-30 | active |
| BE-010 | When a linked member sends the bot text or a voice note, it is stored as an insight (voice transcribed by Deepgram, audio kept in memory only and never stored); an empty transcript is refused; a message starting with `numbers` (any case, then `:`, `,` or a space) gets the weekly-numbers reply; an unlinked user is told how to link Bloomary at most once an hour; a failed save is answered with "Something went wrong". | Content engine plan, Kat 2026-10-30 | active |
| BE-011 | When an MCP client with `drafts:write` calls `attach_image` with base64 data or a public https URL, a JPEG, PNG or GIF (type sniffed from the bytes, max 5 MB) is stored and linked to the member's unpublished draft, replacing its old image; URLs that resolve to non-public addresses are refused. | Content engine plan, Kat 2026-10-30 | active |
| BE-012 | When an MCP client with `insights:write` calls `send_suggestion` (kind `comment`), the linked member gets a Telegram message with the comment, an Open post button, a Copy button (comments up to 256 characters), rating buttons 1–5 and Posted; the suggestion, rating and posted flag are stored. | Content engine plan, Kat 2026-10-30 | active |
| BE-013 | When an MCP client schedules a draft with `schedule_draft`, it publishes at its time; `notify_scheduled` sends the linked member a Telegram preview (text, image, time) (time in Cyprus) with an Edit link and a Skip button, and Skip cancels the schedule unless the post is already going out (the cancel must change the row) or may already be live (`needs_review`); only unpublished drafts can be scheduled. | Content engine plan, Kat 2026-10-30 (no approvals) | active |
| BE-014 | When an MCP client with `insights:read` calls `list_feedback`, it gets each notified post with its outcome (scheduled, published, skipped, failed, ...), the text sent and the current text with a word diff of the member's edits, and comment suggestions with ratings and posted flags. | Content engine plan, Kat 2026-10-30 | active |
| BE-015 | When a member deletes their account or disconnects LinkedIn, their scheduled posts, insights, voice-note attempts, Telegram link, scheduled-post notices, comment and trend suggestions, edit requests, first comments, and AI connector (MCP) grants and app sessions are deleted too. | GDPR, content engine plan 2026-10-30 | active |
| BE-017 | When a linked member replies (voice note, transcribed by Deepgram, or text) to the bot's preview of their own post, the reply (also a reply to the preview's image, never to a preview sent before the current link) is stored as an edit request for that draft, not as an insight, and the bot confirms; a reply to another bot message gets a hint instead; once the post is published, skipped or cancelled the bot says it is too late; at most 20 edit requests a day. MCP clients with `drafts:write` read them with `list_edit_requests` and close them with `mark_edit_applied`. | Kat 2026-10-30 (edit a post by voice) | active |
| BE-018 | When a linked member taps 📅 Planned posts (persistent reply keyboard) or sends /planned, the bot lists their scheduled posts (Cyprus time, first line) with a Preview button each; Preview sends the full post, image and time with How to edit and Skip, counted under its own daily limit; with nothing scheduled the bot points to Drafts. The command menu (/planned, /help) is registered with setMyCommands at start. | Kat 2026-10-30 (bot works like an app) | active |
| BE-019 | When an MCP client with `drafts:write` calls `notify_draft` for an unscheduled, unpublished draft, the linked member gets a preview headed "LinkedIn post draft, not scheduled" with How to edit, Discard (marks the preview skipped, keeps the draft) and an Edit link. | Kat 2026-10-30 (draft-only mode) | active |
| BE-020 | When an MCP client calls `create_draft` or `update_draft` with text containing a link (http(s)://, www. or a bare domain with a path), the call is refused with "links are not allowed in posts" and nothing is stored. | Kat 2026-10-30 (no links in posts), content engine review r1 | active |
| BE-021 | When a linked member sends a voice note (idea or edit reply), the attempt is reserved atomically before transcription: at most 20 attempts and 60 minutes of audio per member per 24 hours, failed and empty transcripts included, and attempts are kept only for that 24-hour window; over the cap nothing is sent to Deepgram and the member is asked to send text. | Content engine review r1 (Deepgram spend cap) | active |
| BE-022 | When Telegram delivers a webhook update, a repeated `update_id` (kept 24 hours) is ignored, and updates are handled one at a time per chat in arrival order, at most 4 chats at once and 500 queued; a panic in one update does not stop the API. | Content engine review r1 | active |
| BE-023 | When an MCP client with `insights:write` calls `send_suggestion` with kind `trend` (any https source URL, summary up to 600 characters), the linked member gets the summary with an Open source button and "Reply with a voice note to turn this into a post"; a voice or text reply to that message is stored as an insight carrying the trend (source URL and summary), which `list_insights` returns as `trend`. Comments (kind `comment`) stay limited to https linkedin.com targets. | Kat 2026-10-30 (daily trends → voice → post) | active |
| BE-024 | When an MCP client passes `first_comment` (up to 1000 characters, links allowed) to `schedule_draft` and the scheduled post publishes, the linked member gets a "First comment" message with the text, a Copy button (up to 256 characters) and an Open post button. | Kat 2026-10-30 (links go in a first comment) | active |
